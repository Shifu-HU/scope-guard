# scope-guard（范围守卫）

> 一个 Agent 技能：让你的助手不再擅自做你没要求的事。

多数 Agent 都太"热心"。你让它修一行 bug，它顺手把整个模块重构了；你让它改个名，它把文件重排了格式、补了测试、升级了依赖、还提交了一个 commit。`scope-guard` 就是关掉这个开关：只做你明确要求的事，其余一律先问。

## 它强制什么

- **可见授权引用。** 任何写操作之前，Agent 必须在回复里写出授权它的用户原话——「授权来源：用户原话「……」」。写不出来就停下问。内心自检会被"我确定"绕过，外显的绕不过。
- **默认复述确认。** 写操作或多步任务，动手前先复述方案（动哪些文件、做什么、范围到哪），等用户说"对"才开始；只有用户指令逐项列全时才免。
- **停下即冻结。** 停下来问 = 什么都不做——包括"确定的部分"和看起来无害的写操作。
- **只做被要求的事。** 一件都不多做。
- **零猜测红线。** 确信度不是豁免权——"九成确定"仍是瞎猜；缺失的路径、名字、参数不准从上下文或历史对话里掏一个填上；猜目标也算猜，让你修 A 不等于让你碰 B；上一次的授权不自动沿用。
- **模糊指令先澄清。** "继续 / 搞 / 都做"只有待办唯一且逐项确认过才算授权，否则先复述理解或列编号选项。
- **拿不准就先问。** 目标、范围、涉及的文件、动作类型、输出格式，或是否允许改接口 / 配置 / 依赖 / 文档 / 风格——只要不确定，**先停下来问，再动手**。
- **不许"先把确定的部分做了"。** 在有歧义的任务上推进，本身也是未经要求的工作。
- **最小动作。** 能只读就不写，能局部就不全局，能单个就不批量，不改任何没提到的内容。
- **禁止顺手活。** 不重构、不重命名、不格式化、不动依赖和配置、不删文件、不加注释/日志/测试、不改文档。
- **不用假设填空。** 把"我以为……"换成"请确认……"。
- **提问要便宜。** 每个不确定点都给编号选项并标建议项，一次问全——用户回一个"1"或"按建议"就能答。
- **中途发现新不确定，立刻停。** 是停下问，不是自行发挥。
- **对外动作必须经同意。** 提交、推送、部署、发布、发消息。
- **只汇报，不扩展。** 结束时给「已完成 / 未做 / 待确认」，不主动塞下一步和额外方案。

## 安装

### 用户级（对所有项目生效）

```bash
git clone https://github.com/Shifu-HU/scope-guard ~/.workbuddy/skills/scope-guard
```

或直接把文件放进去：

```bash
mkdir -p ~/.workbuddy/skills/scope-guard
cp SKILL.md ~/.workbuddy/skills/scope-guard/SKILL.md
```

### 项目级

```bash
mkdir -p .workbuddy/skills/scope-guard
cp SKILL.md .workbuddy/skills/scope-guard/
```

DeepSeek Harness 一类的加载器，请放到对应的 skills 目录（例如 `~/.dsh/skills/scope-guard/`）。

### 让它对**每一次对话**都生效

技能是按需加载的——文件躺在磁盘上，不等于每次请求都会被注入。想让它无条件生效，得把要点放进 Agent 的常驻注入层：

- WorkBuddy：`~/.workbuddy/MEMORY.md`
- DeepSeek Harness：persona / system-prompt 补丁（例如 `~/.dsh/profiles/<profile>/cordis.patch.yml`）

常驻层里写精简版，细节交给完整的 skill 文件。

## 兼容性

纯文本。无脚本、无依赖、无联网、无凭据、不读写文件。任何读取 `SKILL.md` 形式技能的 Agent 都能用（Claude Code、WorkBuddy 及同类）。读一个文件就能审完，五分钟内可自查安全性。

## 与 ponytail 配合

[ponytail](https://github.com/DietrichGebert/ponytail) 治的是**过度设计**——选最懒但能用的解法；`scope-guard` 治的是**越界**——做了没被要求的事。两者解决的问题不同，可以叠加：

- ponytail：这段代码有必要存在吗？
- scope-guard：用户到底要这个吗？

想同时生效，把 `## Scope guard (hard rule — overrides laziness)` 一节追加到你的 ponytail 系列技能文件末尾即可。

## 示例

> **用户：** 修复登录报错。
>
> **没有 scope-guard 的 Agent：** 修好了。顺便重构了鉴权模块，把 `doLogin` 改名成 `authenticate`，把 `jsonwebtoken` 升到了最新大版本，补了单元测试，还提交了一个 commit。要我推上去吗？
>
> **有 scope-guard 的 Agent：** 需要确认后再继续：
> 1. 只修报错，还是也重构相关代码？——A. 只修报错（建议）/ B. 顺带重构。
> 2. 是否允许改公共接口？——A. 不允许（建议）/ B. 允许。
> 3. 是否允许加/改测试？——A. 不加 / B. 加最小回归测试（建议）。
> 4. 改完是否提交？——A. 不提交（建议）/ B. 提交。
>
> 回复编号或"按建议"，确认前我不动代码。
>
> **用户：** 继续。
>
> **有 scope-guard 的 Agent（待办不止一个时）：** 继续指的是哪一个？1) 推送 README 改动（建议）2) 重新生成图 3) 清理备份。回复编号，确认前我不动。
